# Локальный веб-интерфейс

Оба присланных варианта подключены к `forte.api`. CSS, изображения, расположение кнопок и отступы сохранены. Изменены логика запросов и тексты, соответствующие фактическим возможностям прототипа.

После установки проекта запустить `Start-Forte.cmd` из корня либо `scripts/start.ps1`. Открыть на том же компьютере:

- http://127.0.0.1:8000/ — основной вариант со справочником.
- http://127.0.0.1:8000/ui/simple/ — вариант без справочника.

Выбрать MOV/MP4 до 200 МиБ → «Запустить анализ» → дождаться результата → проверить события, таймкоды и кадры. «Проверить другое видео» очищает предыдущий результат. Ошибки анализа выводятся как ошибки, а не как отсутствие нарушений.

## Подключение

Страница и API работают на одном адресе. Перед загрузкой JS вызывает `POST /api/v1/session` с заголовком `X-Forte-Local: 1`. Сервер выдаёт HttpOnly / SameSite=Strict cookie на 8 часов; последующие запросы используют её автоматически. Сессия проверяет локальный адрес, Host, Origin и Sec-Fetch-Site. Секрет в JS не хранится. Внешние API-клиенты могут использовать `X-API-Key` по [контракту](../docs/API.md).

Сервер отдаёт только разрешённые файлы интерфейса, не весь каталог проекта. Статический сервер на 8765 для анализа не подходит.

**Не запускать `main.py` внутри папок фронтенда.** Это сохранённые исходные заглушки из архива: они всегда возвращают отсутствие нарушений. Рабочий сервер находится в корневом модуле `forte.api`.

## Ограничения

Включены 16 экспериментальных визуальных проверок; отчёт содержит все 33 пункта объединённого каталога. Для 17 пунктов детектор не реализован — это показано явно. Проверка ключа использует узкую калибровку замка по 22/23, не распознаёт поворот. Профиль зон рассчитан на известную сцену; произвольные камеры не валидированы. Поддержка воспроизведения MOV зависит от кодека браузера; анализ использует отдельный декодер. Результаты хранятся в памяти сервера, не являются постоянным архивом.

Каталог загружается из /api/v1/rules. Поле rule_checks отображается под результатами в раскрываемом списке. Итоговые заголовки по ТЗ: «Нарушение не обнаружено» / «Обнаружены признаки возможных нарушений». При coverage_status=partial зелёный успешный статус не показывается; ограничения указаны под итогом. Файлы rules.json сохранены как копия каталога для совместимости и тестов, но при работе используется API. Источник события показывается и в варианте без справочника, непосредственно из ответа анализатора.
