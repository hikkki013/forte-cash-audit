Взяты X-15, X-26, X-40, X-25, X-3, шаг 3 сек. На каждом выбранном кадре два запуска: весь кадр и увеличенная область стола. Всего 41 выбранный кадр, 82 запуска модели.

Контактные листы и исходные координаты: `outputs/pilot/`. Время каждого ролика: 4.47–7.13 сек после загрузки модели. Пик выделенной CUDA-памяти PyTorch — 1404.7 МиБ.

Визуальная проверка показала:

- Люди в основном находятся, но есть отражения и дубли рамок.
- На X-26 банкноты после откладывания на стол обнаруживаются; увеличение стола помогает.
- На X-15 оставленный предмет выглядит как закрытая сумка/пакет. Его содержимое по кадрам не установлено. Нельзя автоматически считать любую сумку деньгами.
- Оборудование ошибочно получает метки `bag`/`phone`; одежда кассира получает метку `coat`. Наличие таких меток само по себе не является нарушением.
- Конфигурация стола/места кассира отличается между роликами. Одна таблица координат не решает задачу переноса на другой ракурс.

Поэтому правила для сумок, телефона и пальто в рабочую версию не включены. Классификатор сейфа не обучался и не валидировался.

Первый вариант с единственным текстовым запросом «банкноты» давал ложное распознавание сумки X-15. Добавлены конкурирующие запросы, расширена область стола.

Добавлена зона выхода и минимальная уверенность детекции человека в ней 0.5. Это простая эвристика для известной сцены, не трекинг личности и не универсальная проверка ухода.

## Что нельзя обещать

- Поддержку всех нарушений из таблицы, новых типов и новых камер.
- Надёжное определение «ПК не выключен», «ключ остался», «не проверил удостоверение».
- Автоматически правильную юридическую квалификацию. Каталог содержит предварительные основания для ручной проверки, а не утверждённые ссылки для финальной сдачи.
- Гарантированный запуск на 4 ГБ по факту измерения на RTX 4050 6 ГБ. `max_memory_allocated` не включает всю память CUDA/драйвера.
- Строгий 5-минутный предел на произвольном видео: есть кооперативный таймаут, но нет отдельного процесса, принудительно прерывающего зависший GPU-вызов.

Ближайшая практическая цель — соединить этот ограниченный сценарий с интерфейсом и показать честную демонстрацию, затем расширять покрытие по одному проверенному сценарию.
