# Проверки и оценка качества

[← README](../README.md) · [Инструкция для жюри](JURY_GUIDE.md)

## Три разных уровня

| Уровень | Что проверяет | Чего не доказывает |
| --- | --- | --- |
| Unit/API/frontend tests | Логику кода, очереди, контракты, обработку ошибок | Качество детектора |
| Реальная модель + отдельное видео | Что inference запускается и формирует результат | Качество на всех роликах и типах |
| Независимая оценка на размеченных видео | Точность в определённой области применения | Перенос на любые камеры и неизвестные нарушения |

## Быстрые тесты без GPU и весов

Из корня установленного проекта:

```powershell
powershell -ExecutionPolicy Bypass -File .\scripts\test.ps1
```

Или по отдельности:

```powershell
.\.venv\Scripts\python.exe -m pytest -q
node tests\frontend.cjs
```

Для проверки только кода с нуля, без большого CUDA-пакета:

```powershell
py -3.12 -m venv .venv
.\.venv\Scripts\python.exe -m pip install -r requirements.txt
powershell -ExecutionPolicy Bypass -File .\scripts\test.ps1
```

Этот вариант **не устанавливает PyTorch и веса**; для настоящего анализа потом выполните `scripts/setup.ps1`.

После расширения сценариев локально прошли 84 Python-теста и проверки двух вариантов JS. Проверяется бинарный вердикт с отдельными ограничениями, верхнеуровневые поля API, несколько событий, 1–3 JPEG-кадра, состояния экрана и временные условия. Для наличных проверены полная последовательность, отсутствие входящей/обратной передачи, отсутствие отдельно оставленных банкнот, пропуск кадров, уход клиента, неподходящее исходное расположение и отбрасывание обрезанных/сомнительных детекций. Добавлены проверки смены посетителя, мешков, подавления дублей людей, фоновых предметов и неизвестного состояния сейфа. Это синтетические тесты логики, не оценка точности распознавания. Возможное предупреждение Starlette/AnyIO о deprecated alias не является падением теста.

### Покрытие

Компактные карточки проверяются для всех включённых правил в `tests/frontend.cjs`: обязательные три поля, пометка о перепроверке, отсутствие технических подробностей, безопасные ссылки/экранирование, сохранение статусов и исходных CSS/изображений. Полные метаданные API не удалены.

После добавления калиброванной проверки ключа: **120 Python-тестов**, оба JS-набора успешно. `tests/test_key_state.py` проверяет локальные признаки ключа, сдвиг/яркость, перекрытия, неизвестный ракурс, временную последовательность, отсутствие доказательств и передачу события через Pipeline. Реальные результаты и ограничения пары разработки 22/23 — [KEY_DETECTOR.md](KEY_DETECTOR.md).

После уточнения формулировок 18.10.2026 итоговый прогон: **102 Python-теста**, оба варианта JS — успешно. `tests/test_rule_metadata.py` проверяет метаданные всех 15 включённых правил, совпадение каталогов и различие между сверкой текста и подтверждением применимости. Проверки API и фронтенда дополнены условиями применения п. 25, отсутствием выдуманных источников и экранированием текста/ссылок. Алгоритмы распознавания не менялись; новые прогоны видео для этих редакционных правок не выполнялись.

- `tests/test_multirule.py`: длительность/сброс новых условий, пропуск кадров, неизвестное состояние дверцы, отсутствие автоматического вывода по ручным пунктам, несколько событий и все 28 статусов в Pipeline с явно тестовым детектором. Реальная модель проверяется отдельно, см. [MULTIRULE_PILOT.md](MULTIRULE_PILOT.md).

- `tests/test_rules.py`: непрерывное условие, таймкоды, отсутствие денег/кассира, разрывы, неизвестное состояние сейфа, выключенные правила, последовательность посетителей и зона выхода.
- `tests/test_api.py`: ключ, пустой/слишком большой файл, расширение, очередь, ошибка, выдача результата, очистка временных копий. Здесь используется явно названный **FakeAnalyzer**, а не нейросеть.
- `tests/test_web.py`: раздача обоих интерфейсов, запрет лишних файлов, локальная cookie-сессия, загрузка с ней и блокировка cross-origin/удалённого доступа. Анализатор здесь также тестовый.
- `tests/test_video.py`: создание и реальное декодирование синтетического MP4, PTS, таймаут, повреждённый файл, JPEG и координаты.
- `tests/frontend.cjs`: формулировки, русские названия, экранирование HTML, вложенный `job.result`, отклонение некорректного ответа, отсутствие справочника, неизменность CSS и изображений. Это Node-тесты с имитацией DOM, не полноценный браузерный E2E.

Актуальный статус конкретного коммита смотреть во вкладке Actions, а не выводить из текста README.

## Проверки с реальной моделью

Для проверки полного пользовательского пути запустить `Start-Forte.cmd`, открыть http://127.0.0.1:8000/ и загрузить своё видео. Проверить ожидание, событие с кадрами, отсутствие срабатывания, ошибочный файл и сброс перед следующим видео. Это отдельная браузерная проверка, не Node-тест.

17.10.2026 выполнен ручной сквозной прогон X-26 через веб-интерфейс и настоящий HTTP-сервер: одно событие на 10 секунде, кадры 9/10/13 секунд, обработка 11.2 секунды после загрузки модели. Это проверка интеграции на известном примере, не независимая оценка качества.

После сброса формы через ту же страницу проверен X-25: 17.6 секунды обработки, показано отсутствие событий по включённому правилу и предупреждение об ограниченном покрытии. Предыдущие карточки не сохранились.

Повреждённый MP4 проверен через страницу после перезапуска сервера: показана русская ошибка без приватного пути, положительный/отрицательный вердикт не сформирован. Локальная сессия обновилась автоматически. После завершения проверок временных файлов в runtime/uploads не осталось.

Произвольное разрешённое видео:

```powershell
.\.venv\Scripts\python.exe -m scripts.analyze .\data\videos\example.mov --out outputs\result.json
```

Демонстрационный X-26 через API TestClient:

```powershell
.\.venv\Scripts\python.exe -m scripts.smoke_api --videos .\data\videos
```

Групповой прогон по имеющимся ID:

```powershell
.\.venv\Scripts\python.exe -m scripts.evaluate --videos .\data\videos --ids 24,23,27,14 --out outputs\jury-check
```

`evaluate` сохраняет прогнозы, **не считает метрики по разметке**. Указанные файлы должны существовать; поддерживаются латинское X и кириллическое Х в именах. Исходный набор для этих команд не поставляется через Git.

Пилот сырых детекций, без вывода о нарушении:

```powershell
.\.venv\Scripts\python.exe -m scripts.benchmark --videos .\data\videos --ids 15,26,40,25,3
```

Запускайте GPU-проверки последовательно, чтобы замеры не искажались конкурирующими процессами.

## Как оценивать качество честно

1. До запуска зафиксировать включённые правила, профиль камеры и критерий сопоставления события с разметкой (тип и допустимая ошибка таймкода).
2. Разделить видео для настройки и оценки. Дубликаты и фрагменты одной записи не должны попадать по обе стороны разделения.
3. Для каждого видео проверить сам предмет и действие, а не только совпадение общего ответа «нарушение». Пример проблемы — X-24 в отчёте пилота.
4. Посчитать TP/FP/FN по согласованному правилу сопоставления; определить precision=TP/(TP+FP), recall=TP/(TP+FN), F1 при ненулевых знаменателях. Не заменять отсутствующий знаменатель автоматически на «100%».
5. Публиковать число видео, покрываемые типы, пропуски неподдерживаемых типов, ошибку времени, полную задержку и условия оборудования. Пустые/повреждённые видео учитывать как ошибки обработки, не истинно отрицательные ответы.
6. Изменив пороги после просмотра ошибок, считать этот набор набором разработки. Для следующего утверждения о качестве нужен другой тест.

Текущие числа в [PILOT.md](PILOT.md) — наблюдения разработки и небольшой sanity-check. Репрезентативных метрик на закрытом тесте пока нет.
