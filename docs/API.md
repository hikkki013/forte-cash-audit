# Контракт для интерфейса, v0.1

Локальный Base URL: `http://127.0.0.1:8000`. В режиме жюри используйте
HTTPS-адрес из [JURY_HOSTING.md](JURY_HOSTING.md). Загрузка и чтение заданий
требуют `X-API-Key`; ключ — в `runtime/api-key.txt`. В обычном локальном
интерфейсе используется cookie-сессия, ключ вручную не вводится. В режиме жюри
`FORTE_API_KEY_ONLY=1` отключает это исключение: `analyze` и `jobs` требуют
заголовок от каждого клиента. `/health`, страницы и документация доступны без
ключа.

## Встроенный интерфейс

Визуальные карточки сокращены: название события, таймкод, кадры, «Предполагаемое нарушение. Требует перепроверки» и три дополнительных поля — правило, основание проверки, источник с пунктом. Подробные `description`, `requirement`, `applicability`, `limits`, `legal_status` и данные сверки остаются в JSON без изменений, но не выводятся в карточках, каталоге и пояснениях статусов. Непроверенные/нереализованные пункты по-прежнему явно отмечаются, а не выдаются за успешно пройденные.

`GET /` перенаправляет на `/ui/with-rules/`; второй вариант — `/ui/simple/`. Оба обслуживаются тем же FastAPI. Статика ограничена явным списком файлов.

`POST /api/v1/session` с `X-Forte-Local: 1` выдаёт cookie `forte_local_session` (HttpOnly, SameSite=Strict, 8 часов, Cache-Control: no-store). JSON: `{"ready":true}`; секрет в JSON не возвращается. Встроенный JS вызывает endpoint перед каждой загрузкой. При перезапуске сервера старые сессии недействительны.

Для cookie-запросов нужен `X-Forte-Local: 1`, локальный адрес клиента и Host (127.0.0.1/localhost/::1). Если Origin присутствует, он должен совпадать с адресом запроса; cross-site Sec-Fetch-Site отвергается. Нарушение — HTTP 403. Это интерфейс доверенного пользователя на одном компьютере, не многопользовательская система. В режиме жюри Forte всё ещё запускается только на 127.0.0.1, а Cloudflare Tunnel принимает HTTPS извне и направляет его на этот локальный адрес.

## Загрузка

`POST /api/v1/analyze`, `multipart/form-data`, поле `file`: MOV либо MP4, не более 200 МиБ.

Успех: HTTP 202, `{"job_id":"..."}`. Одна обработка одновременно, максимум два принятых задания (включая ожидающее). При заполнении очереди HTTP 429.

## Получение результата

`GET /api/v1/jobs/{job_id}`. Опрос раз в 1–2 сек. HTTP 200:

```json
{
  "job_id": "...",
  "status": "done",
  "verdict": "violation",
  "violations": [{
    "type": "Возможное оставление банкнот",
    "timecode_sec": 10.0,
    "description": "Описание наблюдения и основания для проверки...",
    "evidence_frames": [{"timestamp_sec": 10.0, "image_base64": "..."}]
  }],
  "result": {
    "verdict": "violation",
    "coverage_status": "partial",
    "violations": [{
      "type": "Возможное оставление банкнот",
      "rule_id": "cash_unattended",
      "timecode_sec": 10.0,
      "confirmed_at_sec": 13.0,
      "review_required": true,
      "description": "Описание наблюдения и ограничения...",
      "evidence_frames": [{"timestamp_sec": 10.0, "image_base64": "..."}]
    }],
    "warnings": ["..."],
    "meta": {
      "model": "grounding-dino-tiny",
      "enabled_rules": ["cash_unattended"],
      "sampled_frames": 20,
      "processing_sec": 11.34,
      "peak_gpu_mb": 1394.2
    }
  },
  "error": null
}
```

Пример сокращён. Поля `verdict` и `violations` находятся на верхнем уровне согласно разделу 10 ТЗ. Объект `result` сохранён для совместимости: он содержит те же события и дополнительные статусы правил, предупреждения и метаданные. Прежние сохранённые ответы в outputs могут отражать старый контракт.

- `processing`: `result=null`, `error=null`.
- `done`: результат доступен; `verdict` строго `violation` или `no_violation`. Наличие одного или нескольких событий даёт `violation`; пустой список — `no_violation`.
- `result.coverage_status`: `partial` при непроверенных пунктах; иначе `complete`. Это покрытие доступных проверок, не гарантия точности модели. Неполнота не заменяет обязательный бинарный вердикт.
- `type`: понятное название события; стабильный машинный идентификатор — `rule_id`.
- `rule_checks`: 33 записей с rule_id, title, status, reason, mode, observed_frames и event_times_sec. Статусы: candidate, not_detected, insufficient_evidence, not_implemented, disabled. Нереализованные пункты не считаются пройденными.
- `GET /api/v1/rules`: публичный каталог режимов и ограничений для интерфейса; ключ не нужен. Источник данных — config/rules.json.
- `violations[].classification == "visual_candidate"`: событие является визуальным предположением. `source_verified: false` означает, что нормативная применимость к конкретному событию не подтверждена; сверка текста PDF не изменяет этот статус.
- `rule_title`, `requirement`, `applicability`, `limits`, `basis_type`, `legal_status`: название проверки, требование, условия применения, ограничения и характер основания. Передаются в событиях, `rule_checks` и публичном каталоге. Наличие ссылки не означает подтверждённого нарушения.
- `source`, `source_title`, `paragraph`: ссылка, название документа и пункт; при отсутствии основания — null. `source_text_verified` относится только к сверке текста предоставленного PDF; `source_snapshot`, `source_pages`, `source_checked_on` указывают документ, страницы и дату сверки. `source_current_verified: false` — актуальность онлайн-редакции не подтверждена.
- `failed`: `result=null`, `error` — текст/код. **Не показывать как «нарушений нет»**.
- `invalid_video_or_configuration`: декодер/настройки не позволили выполнить проверку; приватный путь загрузки не включается в ответ.
- `timecode_sec`: начало наблюдаемого условия. `confirmed_at_sec`: когда накопились условия правила.
- `peak_gpu_mb`: пик allocated-памяти PyTorch, не вся VRAM процесса. На CPU — null.
- Картинка: `src="data:image/jpeg;base64," + frame.image_base64`.
- Заголовки интерфейса строго по ТЗ: «Обнаружены признаки возможных нарушений» / «Нарушение не обнаружено». Ограничения показываются отдельным пояснением. У каждого события — тип, таймкод, описание, 1–3 JPEG-кадра, источник и пункт, если они установлены. Неустановленный источник явно отмечается, ссылки не выдумываются.

Ошибки HTTP: 400 пустой файл, 401 ключ, 404 неизвестное/устаревшее задание, 408 копирование загрузки заняло слишком долго, 413 размер, 415 расширение, 429 очередь, 503 ключ сервера не настроен. Ошибка анализа/повреждённое видео возвращаются как `failed`, не обязательно HTTP 4xx.

## JavaScript

```javascript
export async function analyzeVideo(file, apiKey, onStatus = () => {}) {
  const base = 'http://127.0.0.1:8000';
  const headers = {'X-API-Key': apiKey};
  const body = new FormData();
  body.append('file', file);
  let response = await fetch(base + '/api/v1/analyze', {method: 'POST', headers, body});
  if (!response.ok) throw new Error(await response.text());
  const {job_id} = await response.json();
  const deadline = Date.now() + 300000;
  while (Date.now() < deadline) {
    await new Promise(resolve => setTimeout(resolve, 1500));
    response = await fetch(base + '/api/v1/jobs/' + job_id, {headers});
    if (!response.ok) throw new Error(await response.text());
    const job = await response.json();
    onStatus(job.status);
    if (job.status === 'failed') throw new Error(job.error || 'Ошибка анализа');
    if (job.status === 'done') return job;
  }
  throw new Error('Не удалось дождаться результата');
}
```

Не устанавливать `Content-Type` вручную при отправке FormData. Не зашивать ключ в публичный frontend bundle; это локальная демонстрация для доверенных пользователей, не публичный сервис.

## Эксплуатационные границы

После добавления `key_left_in_lock` включены 16 экспериментальных проверок из 33. Событие ключа содержит полный нормативный контекст п. 80 с оговоркой о внутреннем регламенте; при неподходящей камере/неразличимом замке статус — `insufficient_evidence`. Извлечение, поворот ключа и запирание — разные состояния, см. [KEY_DETECTOR.md](KEY_DETECTOR.md).

После v0.2.0 добавлены `no_client_id`, частичный `no_count_check`,
`count_without_client` и `outsider_in_cashroom`: в текущих исходниках 20 проверок из 33.
Для `door_open` добавлена калибровка стеклянной двери с отказом от решения при
неизвестном виде. Методы, границы и контрольные примеры: [ACCESS_CHECKS.md](ACCESS_CHECKS.md).
`no_count_check` выдаёт `visual_candidate` только после анализа всего фрагмента:
видна последовательность у загрузки и выхода счётной машины, банкноты на столе,
но не наблюдается использование отдельного детектора. Неполная или неоднозначная
последовательность остаётся `insufficient_evidence`. Ручной пересчёт не распознаётся.
См. [CASH_CHECK_CASES.md](CASH_CHECK_CASES.md). Схема ответа и маршруты не менялись.
Сигнал формируется по наблюдаемому визиту и передаче денег без найденного документа;
подтверждение возможно в конце файла. Неполный визит или неоднозначный документ —
`insufficient_evidence`, а не доказательство отсутствия идентификации. Источник этой
записи остаётся непроверенным (`source_text_verified: false`). См.
[метод и регрессию 2/3](IDENTIFICATION_DETECTOR.md). Старый Windows-архив не обновлён.

18.10.2026 формулировки 15 включённых проверок уточнены по предоставленному Adilet.pdf (выгрузка от 17.10.2026). У применимых проверок отмечена сверка текста конкретных пунктов постановления № 231. Проверка текста отделена от подтверждения условий применения к событию и от актуальности онлайн-редакции: последние не подтверждены. Для остальных записей каталога новая нормативная сверка не заявляется. Для проверок без установленного источника возвращаются null и явное пояснение. Сохранённые отчёты содержат снимок метаданных на момент анализа и задним числом не переписываются; для новой карточки нужно перезапустить сервер и повторить анализ.

По умолчанию CORS разрешает `http://localhost:3000` и `http://localhost:5173`. Другой origin задаётся через `FORTE_CORS_ORIGINS` перед запуском. `127.0.0.1` и `localhost` в origin — разные значения.

На другом компьютере `127.0.0.1` указывает на тот компьютер, не на ноутбук автора. Для командной демонстрации сначала запустите интерфейс и backend на одном ноутбуке. Для проверки жюри с другого компьютера используйте отдельный HTTPS-режим из [JURY_HOSTING.md](JURY_HOSTING.md): адрес и ключ передаются только жюри, API-ключ обязателен, а порт 8000 остаётся закрытым извне.

Бюджет обработки — 240 сек после приёма запроса, включая очередь, копирование и холодную загрузку модели. Проверки дедлайна кооперативные: зависший вызов GPU не прерывается принудительно. Это не строгая гарантия «любой файл менее 5 минут». Ограничение размера действует после разбора multipart; публичному серверу нужен внешний ingress-limit.

Хранится около 20 последних заданий; завершённые удаляются при обращениях спустя час. Всё хранится в памяти, без БД. Результат не сохраняется при перезапуске. Health сообщает доступность процесса и наличие файлов, **не качество модели и не готовность CUDA**.
