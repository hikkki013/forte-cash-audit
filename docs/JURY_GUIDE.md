# Инструкция для жюри

[← README](../README.md) · [Тестирование](TESTING.md) · [Ошибки запуска](TROUBLESHOOTING.md)

## 1. Что представлено на проверку

Это ограниченный исследовательский прототип локального видеоанализа. Рабочий путь проверки — **FastAPI либо CLI**. Фронтенд представлен отдельно как макет, он пока не связан с анализатором.

Включён только `cash_unattended`: модель обнаруживает предполагаемые банкноты на столе, отсутствие кассира в заданной рабочей зоне минимум 3 секунды и появление человека в зоне выхода. Вывод требует ручной проверки. Сценарии с документами, ключами, выключением ПК и неизвестными типами нарушений не поддерживаются.

Для повторяемой проверки используйте кадрирование/расстановку рабочего места, соответствующие `config/scene.json`. На другом ракурсе текущую модель правил нельзя считать валидированной. Просмотр полного видео человеком остаётся необходимым.

## 2. Подготовка компьютера

Проверенная среда: Windows x64, Python 3.12, NVIDIA RTX 4050 Laptop с 6 ГБ видеопамяти. Установщик использует PyTorch 2.8.0 с CUDA 12.8; нужен совместимый драйвер NVIDIA. CPU fallback есть, но его скорость не измерялась. Работа на GPU 4 ГБ не проверена.

Для установки нужны интернет, Git и свободное место для окружения, CUDA-пакета, весов и кэша загрузки. Node.js 22+ нужен только для тестов интерфейса. Видео и готовое окружение в репозиторий не входят.

1. Получить доступ к приватному репозиторию от владельца.
2. Клонировать и перейти в каталог:

```powershell
git clone https://github.com/hikkki013/forte-cash-audit.git
cd forte-cash-audit
git rev-parse HEAD
```

Записать SHA коммита в протокол проверки.

3. Установить зависимости:

```powershell
$python312 = py -3.12 -c "import sys; print(sys.executable)"
powershell -ExecutionPolicy Bypass -File .\scripts\setup.ps1 -Python $python312
```

При отсутствии `py` передайте полный путь к установленному Python 3.12. Установка создаёт `.venv`, скачивает зависимости и модель. Скачивание весов — отдельный подготовительный этап, не обработка видео.

4. Проверить доступность CUDA:

```powershell
.\.venv\Scripts\python.exe -c "import torch; print('CUDA:', torch.cuda.is_available()); print(torch.cuda.get_device_name(0) if torch.cuda.is_available() else 'CPU')"
```

Если CUDA=False, не делать выводов о GPU-производительности. Проверить драйвер и установку по [разделу проблем](TROUBLESHOOTING.md).

5. Выполнить проверки кода:

```powershell
powershell -ExecutionPolicy Bypass -File .\scripts\test.ps1
```

Для чистого клона веса берутся из `scripts/download_model.py`: `IDEA-Research/grounding-dino-tiny`, revision `a2bb814dd30d776dcf7e30523b00659f4f141c71`. Сохранённое происхождение весов — `models/grounding-dino-tiny/provenance.json`.

## 3. Где взять видео

Используйте собственные разрешённые видео либо материалы кейса, переданные организаторами/командой отдельно. Репозиторий **не содержит датасет, закрытую разметку или кадры людей**. Отсутствие датасета в Git — намеренное ограничение распространения.

Поместите выбранные файлы, например, в `data/videos/`. Эта папка исключена из Git. Форматы API: MOV/MP4, предел 200 МиБ. Имена файлов не определяют результат анализа. Команды группового пилота ищут конкретные ID только для выбора файлов; pipeline их не получает как метки.

## 4. Проверка через API — основной сценарий

В первом окне PowerShell, из корня проекта:

```powershell
powershell -ExecutionPolicy Bypass -File .\scripts\start.ps1
```

Оставьте окно открытым. Адрес сервера — `http://127.0.0.1:8000`, интерактивная документация — `http://127.0.0.1:8000/docs`.

### Ключ доступа

При первом запуске создаётся `runtime/api-key.txt`. Откройте файл локально и скопируйте ключ. Не публикуйте его в GitHub, скриншотах или отчётах. В Swagger у запросов есть поле `x-api-key`; вводите ключ там, не в URL. Если заранее задана переменная `FORTE_API_KEY`, используется её значение вместо файла.

### Загрузка и получение ответа

1. Открыть `POST /api/v1/analyze` → **Try it out**.
2. Указать `x-api-key`, выбрать видео в поле `file` → **Execute**.
3. Ожидаемый ответ HTTP 202: `{"job_id":"..."}`.
4. Открыть `GET /api/v1/jobs/{job_id}` → **Try it out**.
5. Вставить `job_id`, указать тот же ключ → **Execute**.
6. При `processing` повторять GET примерно раз в 1–2 секунды. Повторно загружать видео не требуется.
7. При `done` сохранить JSON результата. При `failed` записать поле `error`; это ошибка проверки, не отрицательный результат.

Выполняется одна обработка одновременно, в системе допускаются две принятые задачи, включая ожидающую. Третья получает HTTP 429. Для замеров запускайте видео последовательно, без других GPU-задач.

Первый запрос включает загрузку модели. `meta.processing_sec` измеряет анализ после загрузки; для полной задержки отдельно измеряйте время от POST до окончательного GET.

### Интерпретация

`result.verdict == "violation"` означает срабатывание эвристического правила, не доказанное нарушение закона. `review_required` требует проверки человеком.

`result.verdict == "no_violation"` означает отсутствие срабатывания **единственного включённого правила**, а не отсутствие нарушений любого вида.

`timecode_sec` — начало условия; `confirmed_at_sec` — момент подтверждения. `evidence_frames` содержит JPEG в base64 и исходные таймкоды. В интерфейсе интегратора изображение выводится через `data:image/jpeg;base64,` плюс содержимое `image_base64`. Кадры не являются сгенерированными иллюстрациями.

Подробная схема — [API.md](API.md). Сервер не хранит результаты после перезапуска; сохраните JSON до остановки.

## 5. Проверка через командную строку

Не требует запуска HTTP-сервера, но требует установленной модели:

```powershell
.\.venv\Scripts\python.exe -m scripts.analyze "C:\Videos\example.mov" --out outputs\jury-result.json
```

Заменить путь на существующий файл. Команда выведет краткий результат и сохранит полный JSON, включая наблюдения по кадрам. При ошибке процесс завершится с ненулевым кодом; это не результат `no_violation`.

Для другого профиля сцены:

```powershell
.\.venv\Scripts\python.exe -m scripts.analyze "C:\Videos\example.mov" --scene config\scene.json --out outputs\jury-result.json
```

Не менять зоны/пороги по ответам тестовых видео, а затем объявлять эти же видео независимым тестом. Любые изменения профиля фиксировать в протоколе.

## 6. Повторение демонстрационного примера

Если у жюри есть исходный X-26 из материалов кейса:

```powershell
.\.venv\Scripts\python.exe -m scripts.smoke_api --videos .\data\videos
```

Это настоящий прогон модели через FastAPI TestClient в текущем процессе, не HTTP-проверка отдельного uvicorn и не тест через фронтенд. Скрипт ожидает хотя бы одно событие в демонстрационном X-26; применим только к этому примеру. В нём фиксированный тестовый ключ используется лишь внутри TestClient и не является ключом сервера.

Создаются `outputs/api-smoke/response.json` и `openapi.json`. Для просмотра настоящих кадров этого прогона:

```powershell
.\.venv\Scripts\python.exe -m scripts.export_evidence
```

Открыть `outputs/api-smoke/evidence.jpg`. Подтверждённое локальное наблюдение: начало 10 сек, подтверждение 13 сек. Это development-пример, не закрытый тест качества.

## 7. Что записывать в протокол оценки

- SHA коммита, ревизию модели, Python/PyTorch, CPU/GPU, объём VRAM.
- Идентификатор/хеш видео, длительность, разрешение, профиль сцены.
- Успех обработки или ошибку; полный latency и отдельно `processing_sec`.
- Тип события, начало и подтверждение, кадры, замечания проверяющего.
- Ложные тревоги, пропуски и ошибочно распознанные предметы — отдельно.

Типы нарушений вне текущего покрытия не исключать молча из общей оценки. Не считать соседние кадры одного видео независимыми тестами. Подробная методика — [TESTING.md](TESTING.md).

## 8. Остановка и границы готовности

Остановить сервер: Ctrl+C в его окне. Оригиналы видео не изменяются; временная копия загрузки удаляется после задания. При аварийном завершении копии могут остаться в `runtime/uploads`. Результаты CLI в `outputs` нужно удалять отдельно согласно правилам хранения данных команды.

Не запускать `frontend/*/main.py`: это заглушка из примера интерфейса. Не объявлять показанный макет полноценным сквозным пользовательским сценарием. Не заявлять, что все требования конкурса выполнены: интеграция интерфейса, расширение сценариев, проверка юридических ссылок и перенос на новые ракурсы ещё предстоят.
