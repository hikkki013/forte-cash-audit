# Работа команды

1. Получить доступ к приватному репозиторию и клонировать его. Не пересылать личные GitHub-токены.
2. Создать отдельную ветку для своей задачи, например `feature/frontend-integration`.
3. Не менять оформление интерфейса без согласования: CSS, кнопки и отступы сохранены по просьбе команды.
4. До коммита запустить `scripts/test.ps1`. После изменений модели/правил выполнить отдельные прогоны видео и записать ошибки, а не только успешные примеры.
5. Перед отправкой проверить `git diff --cached --stat` и сами изменения. Не использовать `git add -f` для видео, весов или секретов.
6. Создать pull request с описанием: что изменено, как проверено, какие ограничения остались. Не выдавать mock-тест за реальный inference.

## Не добавлять в Git

API-ключи, `.env`, `runtime`, `.venv`, `models`, `outputs`, исходные видео и архивы датасетов. Результаты с кадрами людей — тоже данные, а не обычные тестовые артефакты. Jupyter notebooks коммитить без outputs/attachments и секретов.

## Следующая задача

Оба интерфейса подключены к `forte.api` с сохранением дизайна. Следующий шаг — независимая проверка сценария и последовательное расширение покрытия. Контракт — [docs/API.md](docs/API.md). Не использовать `frontend/*/main.py` как рабочий backend.

## Доступ жюри

Репозиторий остаётся приватным. Приглашения участникам/жюри отправляет владелец после согласования конкретных аккаунтов. Наличие ссылки само по себе не предоставляет доступа. Не менять видимость на публичную ради устранения ошибки 404 без отдельного решения владельца.
